# Zenn 記事作成スキル

記事のネタから読者・ゴール・構成を固め、`articles/` に骨組みを作る。

**出力言語: 日本語**

## ワークフロー

### 0. スキル使用の明示

「**article** skill を使います。」と発言してから作業開始。

### 1. ガイド読み込み

`.agents/references/zenn-writing-guide.md` を読み込む。以降のすべての判断でこのガイドに従う。

### 2. ヒアリング

引数または対話で以下を確認する。引数にネタだけが渡された場合、残りは対話で埋める。

| 項目 | 必須 | 説明 |
|---|---|---|
| ネタ | yes | 何について書くか |
| 記事タイプ | yes | A: トラブルシュート / B: 技術紹介・導入手順 / C: 検証・比較 / D: 事例・ポエム |
| 読者 | yes | 誰に読んでほしいか。どんな状況で検索してくる人か |
| 持ち帰り | yes | 読み終えた読者が何をできるようになるか（1文で） |
| 手元の材料 | no | コード・ログ・スクリーンショット・計測結果の有無 |

記事タイプが自明でない場合は、ネタから推定して確認する。

- 「〜が遅かった」「料金が跳ねた」「動かなかった」→ A
- 「〜を作った」「〜を導入した」→ B
- 「〜と〜を比べた」「どっちが速い」→ C
- 「〜という運用をしている」「〜だと思う」→ D

### 3. 既存記事との重複チェック

`articles/*.md` の frontmatter を走査し、同じテーマの記事がないか確認する。
既存記事がある場合はユーザーに提示し、新規作成 / 既存記事の更新 / 続編として書く のいずれかを確認する。
続編の場合は、既存記事へのリンクを導入部に入れる。

### 4. タイトル・frontmatter の決定

タイトル案を3つ提示し、選んでもらう。案には以下を織り交ぜる。

- 検索語を含む素直な案（例: `Langfuse の Sentry 統合で料金が跳ねた原因と対処`）
- ツール名を角括弧で前置する案（例: `[Langfuse] Sentry 統合時の Span 送信を絞る`）
- 事象を主語にした案（例: `Langfuse を Sentry統合で導入した際に料金が大変なことになった話`）

決まったら frontmatter を組み立てる。

- `emoji`: 🦒 を既定とし、内容に強く寄せたい場合のみ変更を提案する
- `topics`: 1〜5個。**Zenn に実在するトピック名と正確に一致させる**。表記に自信がない場合は WebSearch で `zenn.dev/topics/<候補>` を確認する
- `published`: 必ず `false`

### 5. ファイル作成

```bash
npx zenn new:article
```

生成された `articles/<14桁hex>.md` を frontmatter で上書きする。
zenn-cli が使えない場合は、既存記事と衝突しない14桁の16進数を自分で決めてファイルを作成する。

### 6. アウトライン提示

ガイドの「記事タイプ別の構成テンプレート」から該当タイプを選び、ネタに合わせて見出しを具体化する。
見出しごとに「そこで何を書くか」を1〜2行で添えて提示し、承認を得る。

```
## 想定外の料金使用料通知が届く
  → Sentry の請求アラートのスクショ。前月比の倍率。何にびっくりしたか

## 原因 - OpenTelemetry の Span が全部送られていた
  → thinkingConfig ではなく上流に置いた OTel の挙動。ドキュメントの該当箇所を引用
```

承認前に本文を書き始めない。

### 7. 骨組みの書き出し

承認されたアウトラインを Markdown に落とす。

- 導入部（自己紹介＋記事の要約）は**完成形で書く**
- 各セクションは見出しと、`<!-- ここに書くこと: ... -->` 形式のメモを置く
- コード・画像が入る箇所は `<!-- コード: ... -->` `<!-- 画像: ... -->` で位置を示す
- 締めのセクション（`## おわりに` / `## 参考`）まで用意する

材料（コード・ログ・計測結果）が既に手元にある場合は、該当セクションを埋めてよい。

### 8. 完了報告

```
Done:
- 作成: articles/<slug>.md
- タイトル: <title>
- タイプ: <A/B/C/D>

次の工程:
- 本文を書く（`npx zenn preview` でプレビュー）
- /fact-check   バージョン・料金・API 名の裏取り
- /code-verify  コードブロックの動作検証
- /writing-check 文章の推敲
- /disclosure-check 社外秘スクリーニング
- /publish-check 公開前の最終ゲート
```

## ルール

1. **ガイド厳守**: `.agents/references/zenn-writing-guide.md` の構成テンプレート・frontmatter 規約に従う
2. **アウトライン承認が先**: 見出し構成の承認前に本文を書かない
3. **`published: false` 固定**: このスキルで `true` にしない。`publish-check` の役目
4. **topics は実在確認**: 推測でトピック名を書かない。表記が違うと流入しない
5. **導入部は完成形で**: 読者が離脱するか決まる箇所なので、骨組み段階でも書き切る
6. **既存記事を確認**: 重複・続編の判断を飛ばさない
7. **画像は作らない**: プレースホルダーで位置だけ示す
