# 社外秘スクリーニングスキル

業務で得た知見を記事にする以上、**書いてよい情報と書いてはいけない情報の線引き**が必要になる。
本文・コード・画像を横断して検出し、公開できる形への言い換えまで提案する。

**このスキルは最終判断をしない。判断材料を揃えて人間に渡すのが役割。**

**出力言語: 日本語**

## ワークフロー

### 0. スキル使用の明示

「**disclosure-check** skill を使います。」と発言してから作業開始。

### 1. 対象記事の特定

引数指定 → 未コミットの `articles/*.md` → 最終更新が最新のファイル、の順で決める。

### 2. 本文・コードのスクリーニング

以下のカテゴリを網羅的にチェックする。

| # | カテゴリ | 検出するもの |
|---|---|---|
| 1 | **顧客・取引先** | 実名、業種＋規模＋時期の組み合わせで特定できる記述、ロゴ、契約の存在自体 |
| 2 | **未公開情報** | 未リリースの機能、ロードマップ、開発中のプロダクト名、社内でのみ共有されている方針 |
| 3 | **認証情報** | API キー、トークン、パスワード、秘密鍵、`op://` 参照、`.env` の実値、DB 接続文字列、Cookie |
| 4 | **内部 URL・ID** | 社内 Notion / Slack / Jira / Confluence の URL、内部管理画面、Intercom 記事 ID、社内リポジトリの URL、Datadog / Sentry のダッシュボード URL |
| 5 | **インフラ詳細** | ホスト名、内部 IP、AWS アカウント ID、ARN、S3 バケット名、本番サブドメイン、VPC / セキュリティグループ ID、k8s の namespace 構成 |
| 6 | **金額・契約** | 自社が支払っている実額、ベンダーとの契約単価、値引き条件、利用規模（リクエスト数・ユーザー数の実数） |
| 7 | **個人情報** | 同僚・関係者の実名、顔写真、メールアドレス、Slack の表示名やアイコン、社内の人事情報 |
| 8 | **社内コード** | 社内リポジトリのコードをそのまま貼っている箇所、独自ドメインロジック、内部 API のスキーマ |
| 9 | **組織の内情** | 特定できる形での組織批判、離職・採用の事情、社内トラブルの詳細 |

`Grep` で機械的に拾えるパターン（`sk-`, `ghp_`, `AKIA`, `op://`, `.internal`, `10.0.`, `192.168.`, 自社ドメイン等）と、
読解が必要なもの（顧客の特定、未公開機能）の両方を実施する。

### 3. 画像のスクリーニング

記事が参照しているすべての画像を **`Read` で実際に開いて中身を確認する**。ファイル名だけで判断しない。

チェックする内容:

- スクリーンショット内のテキスト（URL バー、タブ名、通知、サイドバーの項目名）
- Slack / Notion のスクショに写り込んだ発言者名・アイコン・チャンネル名・他の投稿
- 管理画面に表示されている顧客名・実数値・ユーザー一覧
- ダッシュボードの金額・リクエスト数
- IDE のスクショに写ったファイルツリー・他のタブ・社内リポジトリ名
- ブラウザのブックマークバー・拡張機能

見つかった場合は「画像 `<name>.png` の <どこ> に <何> が写っている」と位置まで具体的に報告し、
マスキングか差し替えを提案する。

### 4. 判定と言い換え提案

| 判定 | 意味 |
|---|---|
| 🔴 **削除必須** | 認証情報、顧客実名、未公開機能、個人情報。そのまま公開してはいけない |
| 🟡 **要言い換え** | 情報としては書けるが、抽象化・ぼかしが必要 |
| 🟢 **問題なし** | 公開済み情報・一般的な技術情報 |
| ❓ **要相談** | 判断がつかない。上長・法務に確認すべき |

**🔴 と 🟡 には必ず言い換え案を添える。** 記事の価値を残したまま公開できる形にするのが目的で、
単に消させるのが目的ではない。

```
【🟡 要言い換え】L23 — 金額の実数値

Before:
> 月額 $12,000 の請求が来て青ざめました。

After（案1・倍率で示す）:
> 想定の30倍を超える請求が来て青ざめました。

After（案2・オーダーだけ示す）:
> 月額で数千ドル規模の請求が来て青ざめました。

理由: 実額から利用規模と契約条件が推定できます。
      読者に伝わる「想定外に大きかった」という情報は倍率で十分に表現できます。
```

```
【🟡 要言い換え】L88 — 顧客が特定できる記述

Before:
> 従業員3万人規模の大手製造業のお客様で、2026年3月から導入いただいており

After:
> 従業員数万人規模のエンタープライズのお客様で

理由: 規模・業種・時期の組み合わせで特定される可能性があります。
```

### 5. レポート提示

```
## 社外秘スクリーニング: articles/<slug>.md

判定: 🔴<N>件 / 🟡<N>件 / ❓<N>件 → 現時点では **公開不可 / 要修正 / 公開可**

### 🔴 削除必須
（箇所・内容・対処）

### 🟡 要言い換え
（Before/After）

### ❓ 要相談
（判断が必要な理由と、確認すべき相手）

### 確認した画像
| 画像 | 判定 | 内容 |
|---|---|---|
| langfuse_cto_slack.png | 🟡 | Slack の発言者アイコンと表示名が写り込み。マスキング推奨 |
```

### 6. 修正の適用

ユーザー承認後に本文を修正する。画像のマスキングは行わない（**位置を指摘するに留め、加工はユーザーに任せる**）。

### 7. 完了報告

```
Done: articles/<slug>.md

検出: 🔴<N> / 🟡<N> / ❓<N>
適用: <N>件
残: <N>件（要判断）

⚠️ このスキルの結果は判断材料です。最終的な公開可否は人間が判断してください。
   ❓ の項目は公開前に上長・法務への確認を推奨します。
```

## ルール

1. **迷ったら厳しい側に倒す**: 判断がつかないものを 🟢 にしない。❓ として上げる
2. **画像は必ず開く**: `Read` で実際に中身を見る。ファイル名からの推測で済ませない
3. **言い換え案を必ず付ける**: 「消してください」で終わらせない。記事の価値を保つ書き換えを提案する
4. **最終判断をしない**: 「公開して問題ありません」と断定しない。判断材料を揃えて人間に渡す
5. **画像を加工しない**: マスキング位置は指摘するが、加工はユーザーの手で行ってもらう
6. **組み合わせで考える**: 単体では無害な情報も、組み合わせると特定に繋がる（業種＋規模＋時期、技術構成＋求人票）
7. **検出漏れの前提を伝える**: このスキルが 🟢 でも見落としの可能性はある。完全性を保証しない
8. **過去記事の再点検も受ける**: 公開済み記事に対して実行された場合も同じ手順で診断する
