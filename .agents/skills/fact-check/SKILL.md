# 裏取り調査スキル

記事に書かれた事実の主張を洗い出し、一次情報にあたって検証する。
技術記事は公開後も読まれ続けるため、**執筆時点を明記したうえで、その時点の正確性を担保する**。

**出力言語: 日本語**

## ワークフロー

### 0. スキル使用の明示

「**fact-check** skill を使います。」と発言してから作業開始。

### 1. 対象記事の特定

引数指定 → 未コミットの `articles/*.md` → 最終更新が最新のファイル、の順で決める。
複数候補がある場合はユーザーに確認する。

### 2. 検証対象の抽出

記事を読み、**検証可能な事実の主張**をすべてリストアップする。以下のカテゴリで漏れなく拾う。

| カテゴリ | 例 |
|---|---|
| バージョン番号 | 「Next.js 15 では」「zenn-cli v0.1.151」 |
| 料金・課金体系 | 「Langfuse の Free プランは月5万イベントまで」「$0.30 / 1M tokens」 |
| API・オプション名 | `thinkingConfig`、`--help-center-id`、`generateObject()` |
| 仕様の断定 | 「Gemini はデフォルトで thinking が有効」「Zenn の topics は5つまで」 |
| 挙動の説明 | 「OpenTelemetry は上流に設置すると配下の呼び出しをすべて拾う」 |
| 他社製品の記述 | 「Cursor の Plan モードは〜」「Intercom の記事 API は〜」 |
| 日付・時系列 | 「2025年6月にリリースされた」「当時はまだ〜」 |
| 引用・リンク | 記事中の URL、引用したドキュメントの文面 |
| 数値・計測結果 | ベンチマーク値、「10倍速くなった」 |

抽出したリストをユーザーに提示してから調査に入る。件数が多い場合は優先度を確認する。

### 3. 一次情報での検証

主張ごとに情報源を当たる。**優先順位を守る**。

1. 公式ドキュメント
2. 公式リリースノート / CHANGELOG / GitHub のソースコード・Issue
3. 公式ブログ・公式アナウンス
4. 第三者の記事・Stack Overflow（**単独の根拠にしない。裏付けの手がかりとしてのみ使う**）

`WebSearch` で探し、`WebFetch` で本文を読む。
ローカルで確認できるもの（`package.json` の依存バージョン、`node_modules` の型定義）はファイルを直接読む。

### 4. 判定

| 判定 | 意味 | 対応 |
|---|---|---|
| ✅ | 一次情報で裏取り済み | 出典 URL を記録 |
| ⚠️ | 執筆当時は正しいが現在は変わっている | 「〇〇年〇月時点」の注記を追加、または現行仕様に更新 |
| ❌ | 誤り | 修正案を提示 |
| 🔍 | 一次情報が見つからない | 断定を避ける表現に書き換える提案 |
| 💭 | 検証不能な主観・体験 | 「筆者の環境では」と条件を明示する提案 |

### 5. レポート提示

```
## 裏取り結果: articles/<slug>.md

| # | 主張 | 判定 | 出典 |
|---|------|------|------|
| 1 | Gemini 2.5 Flash はデフォルトで thinking が有効 | ✅ | https://ai.google.dev/... |
| 2 | Langfuse Free は月5万イベント | ⚠️ | 現在は月3万。https://langfuse.com/pricing |
| 3 | OTel の Span は自動で全部送られる | 🔍 | 一次情報なし。条件付きの記述に変更を推奨 |

### ❌ 誤り（要修正）
（該当箇所と修正案を Before/After で）

### ⚠️ 変化あり（要更新）
（当時と現在の差分。時点注記の追加案）

### 🔍 一次情報なし
（断定を避ける書き換え案）
```

### 6. 記事への反映

ユーザー承認後、以下を適用する。

- 誤りの修正、変化した情報の更新
- 変化しやすい情報を含む箇所に**時点注記**を入れる
  - 記事冒頭: `:::message\n本記事の内容は 2026年8月時点のものです。\n:::`
  - 個別箇所: 「2026年8月時点では〜」
- `## 参考` セクションに出典を追加する

```markdown
## 参考

- [Gemini API - Thinking](https://ai.google.dev/gemini-api/docs/thinking) — thinkingConfig の仕様
- [Langfuse Pricing](https://langfuse.com/pricing) — 無料枠の上限
```

### 7. 完了報告

```
Done: articles/<slug>.md

検証: <N>件（✅<N> / ⚠️<N> / ❌<N> / 🔍<N> / 💭<N>）
修正: <N>件を適用
追加: 時点注記 <N>箇所、出典 <N>件

要判断:
- <ユーザーの判断が必要な項目>
```

## ルール

1. **一次情報にあたる**: 第三者ブログだけを根拠にしない。公式が見つからない場合は 🔍 と判定する
2. **URL を必ず記録する**: 「調べたら合っていた」で済ませない。検証した URL を必ず出す
3. **確認日を添える**: 料金や仕様は変わる。レポートに確認日を明記する
4. **推測を事実として書かない**: 検証できなかったものは 🔍 のまま報告し、勝手に補完しない
5. **時点注記を提案する**: バージョン・料金・UI に触れる記事には必ず「〇〇年〇月時点」を提案する
6. **主観は主観のまま残す**: 「体感で速くなった」は誤りではない。条件を添える提案に留める
7. **勝手に書き換えない**: 承認前にファイルを編集しない
8. **記事の主張を弱めすぎない**: すべてを「〜のようです」にしない。裏取りできたものは断定してよい
